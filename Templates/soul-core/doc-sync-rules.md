# 🔄 文档同步自动化规则

> 代码变了，文档必须跟着变。Code ≠ Doc is a bug。

---

## 核心原则

1. **文档先于代码** — 写代码前先确认文档
2. **代码跟随文档** — 代码必须与文档一致
3. **改码必更文** — 任何代码变更必须同步更新文档
4. **自动检查** — AI 每次执行后自动检查文档一致性

---

## 同步规则表

### 代码变更 → 必须更新的文档
| 代码变更类型 | 必须更新的文档 | 更新内容 |
|-------------|----------------|----------|
| 新增模块 | ARCH.md | 模块划分、输入输出 |
| 修改模块逻辑 | ARCH.md | 数据流、依赖关系 |
| 新增 API 接口 | ARCH.md + PRD.md | 接口定义、功能说明 |
| 修改 API 参数 | ARCH.md | 接口详情 |
| 修改算法逻辑 | ARCH.md | 关键决策、技术选型 |
| 新增数据库表 | ARCH.md | 数据模型 |
| 修改数据库字段 | ARCH.md | 表结构 |
| 新增/修改策略信号 | ARCH.md (量化) | 信号定义、参数 |
| 修改风控参数 | ARCH.md (量化) | 风控规则 |
| 修改执行逻辑 | ARCH.md (量化) | 执行流程 |

### 测试变更 → 必须更新的文档
| 测试变更类型 | 必须更新的文档 | 更新内容 |
|-------------|----------------|----------|
| 新增测试用例 | TEST.md | 测试矩阵 |
| 测试结果更新 | TEST.md | 通过/失败状态 |
| 发现 Bug | TEST.md + LOG.md | Bug 记录 |
| Bug 修复 | TEST.md + LOG.md | 修复记录 |

### 需求变更 → 必须更新的文档
| 需求变更类型 | 必须更新的文档 | 更新内容 |
|-------------|----------------|----------|
| 新增功能 | PRD.md + ARCH.md | 需求清单 + 架构 |
| 删除功能 | PRD.md + ARCH.md | 需求清单 + 架构 |
| 修改优先级 | PRD.md | 优先级标注 |
| 新增约束 | PRD.md | 约束条件 |

---

## 自动化检查流程

### 每次代码变更后自动执行
```
1. 识别变更类型（新增/修改/删除）
2. 查找对应文档章节
3. 对比代码与文档
4. 如不一致 → 自动更新文档
5. 提交文档变更到 Git
6. 记录到 LOG.md
```

### 一致性检查规则
| 检查项 | 检查方法 | 不一致时 |
|--------|----------|----------|
| 模块数量 | 代码模块数 vs ARCH 模块表 | 更新 ARCH |
| API 接口 | 代码路由 vs ARCH 接口表 | 更新 ARCH |
| 数据库表 | 代码建表 vs ARCH 表结构 | 更新 ARCH |
| 策略信号 | 信号函数 vs ARCH 信号定义 | 更新 ARCH |
| 风控参数 | 代码参数 vs ARCH 风控规则 | 更新 ARCH |

---

## 禁止行为
- ❌ 修改代码不更新文档
- ❌ 更新文档不提交 Git
- ❌ 文档与代码不一致继续开发
- ❌ 合并代码不检查文档同步

## 强制行为
- ✅ 每次代码变更后自动检查文档
- ✅ 发现不一致自动修复
- ✅ 文档变更自动提交 Git
- ✅ 所有变更记录到 LOG.md
