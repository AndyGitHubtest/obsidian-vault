# 🤖 Hermes SOUL 自动化执行规则

> 本文档定义 AI 在每个阶段**自动执行**的动作，无需人工干预

---

## 总原则

1. **能自动的不问** — AI 自动判断、自动执行、自动记录
2. **文档先于代码** — 没有文档，AI 自动创建后再执行
3. **失败自动回滚** — 任何阶段失败，AI 自动回到上阶段
4. **全程自动记录** — 每一步自动写入 LOG.md
5. **状态自动流转** — 条件满足自动进入下一阶段

---

## INIT 阶段 — AI 自动执行

### 触发条件
- 用户输入项目需求（一句话或详细描述）

### AI 自动动作
```
1. 解析用户输入 → 提取项目目标、类型、约束
2. 判断项目类型 → 开发项目 or 量化策略
3. 创建项目目录结构 → 按 project-scaffold 标准
4. 复制 SOUL 核心文件 → status.md, Task.md, LOG.md, CHECKLIST.md
5. 填写 Task.md → 自动拆解任务，生成子任务清单
6. 填写 status.md → STATUS: INIT
7. 写入 LOG.md → 记录初始化操作
8. 初始化 Git → git init + commit
9. 自检 → 检查所有文件是否就绪
10. 自动流转 → 条件满足则进入 PLANNING
```

### 自动产出
- Task.md（任务拆解）
- status.md（INIT）
- LOG.md（初始化记录）

### 流转条件（自动判断）
- ✅ 进入 PLANNING：Task.md 任务拆解完成，项目类型明确
- ❌ 停留 INIT：用户需求不清晰 → AI 自动补充假设并标注

---

## PLANNING 阶段 — AI 自动执行

### 触发条件
- INIT 阶段完成，自动进入

### AI 自动动作
```
1. 读取 Task.md → 获取项目目标
2. 选择对应模板 → dev-templates 或 quant-templates 的 01
3. 填充 PRD.md → 根据 Task.md 自动填写
4. 补充需求细节 → AI 自动分析遗漏并补充
5. 识别风险 → AI 自动列出潜在风险
6. 明确不做范围 → AI 自动排除不合理需求
7. 写入 LOG.md → 记录 PLANNING 操作
8. 更新 CHECKLIST.md → 标记 INIT→PLANNING 检查项
9. 自检 → 检查 PRD 完整性
10. 自动流转 → 条件满足则进入 DESIGN
```

### 自动产出
- PRD.md（完整需求文档）

### 流转条件（自动判断）
- ✅ 进入 DESIGN：PRD 完整填写，目标明确，范围清晰
- ❌ 停留 PLANNING：PRD 关键项缺失 → AI 自动补全

---

## DESIGN 阶段 — AI 自动执行

### 触发条件
- PLANNING 阶段完成，自动进入

### AI 自动动作
```
1. 读取 PRD.md → 获取需求清单
2. 选择对应模板 → dev 或 quant 的 02 阶段模板
3. 填充 ARCH.md → 设计系统架构
4. 模块划分 → AI 自动拆分模块，定义输入输出
5. 技术选型 → AI 根据需求自动推荐
6. 数据流设计 → AI 自动描述数据流向
7. 关键决策记录 → AI 自动记录 ADR
8. 风险点分析 → AI 自动列出技术风险
9. 覆盖性检查 → 确认 ARCH 覆盖所有 PRD 需求
10. 写入 LOG.md → 记录 DESIGN 操作
11. 自检 → 检查 ARCH 完整性
12. 自动流转 → 条件满足则进入 DEVELOP
```

### 自动产出
- ARCH.md（架构设计文档）

### 流转条件（自动判断）
- ✅ 进入 DEVELOP：ARCH 覆盖所有 PRD 需求，模块边界清晰
- ❌ 停留 DESIGN：ARCH 未覆盖 PRD → AI 自动补充

---

## DEVELOP 阶段 — AI 自动执行

### 触发条件
- DESIGN 阶段完成，自动进入

### AI 自动动作
```
1. 读取 ARCH.md → 获取模块清单和依赖关系
2. 读取 Task.md → 获取开发任务清单
3. 按依赖顺序执行任务 → T1 → T2 → T3
4. 每个任务完成后：
   a. 编写/修改代码
   b. 语法检查 / 编译验证
   c. 更新文档（如代码与文档不一致）
   d. 提交 Git
   e. 更新 Task.md 任务状态
   f. 写入 LOG.md
5. 全部任务完成后：
   a. 代码完整性检查
   b. 编译/语法检查
   c. 文档同步检查
6. 自检 → 检查所有 P0 任务完成
7. 自动流转 → 条件满足则进入 TEST
```

### 自动产出
- 可运行代码
- 更新的 Task.md
- 更新的 LOG.md

### 流转条件（自动判断）
- ✅ 进入 TEST：所有 P0 任务完成，代码无编译错误，文档已同步
- ❌ 停留 DEVELOP：任务未完成或有编译错误 → AI 自动修复

### 错误处理（自动）
- 编译错误 → AI 自动修复，记录到 LOG.md
- 文档不一致 → AI 自动更新文档
- Git 冲突 → AI 自动解决冲突

---

## TEST 阶段 — AI 自动执行

### 触发条件
- DEVELOP 阶段完成，自动进入

### AI 自动动作

#### 开发项目
```
1. 读取代码 → 分析测试覆盖范围
2. 生成测试用例 → 按 TEST.md 模板
3. 执行单元测试 → 自动运行
4. 执行集成测试 → 自动运行
5. 分析结果 → 通过率、覆盖率
6. 如有失败：
   a. 记录失败用例到 TEST.md
   b. 记录到 LOG.md
   c. 自动回滚到 DEVELOP
   d. 修复后重新进入 TEST
7. 全部通过 → 自动流转到 DEPLOY
```

#### 量化策略
```
1. 读取策略代码 → 确认回测配置
2. 准备测试数据 → 确认数据完整性
3. 执行回测 → 自动运行回测引擎
4. 分析结果：
   a. Sharpe、回撤、胜率、盈亏比
   b. 样本外验证
   c. 参数敏感性测试
   d. 极端行情测试
5. 指标不达标：
   a. 记录到 TEST.md
   b. 记录到 LOG.md
   c. 自动回滚到 DEVELOP
   d. 调整参数/逻辑后重新回测
6. 指标达标 → 自动流转到 DEPLOY
```

### 自动产出
- TEST.md（测试报告）
- 测试结果数据

### 流转条件（自动判断）
- ✅ 进入 DEPLOY：测试全部通过，指标达标
- ❌ 回滚 DEVELOP：测试失败 → AI 自动修复后重新测试

---

## DEPLOY 阶段 — AI 自动执行

### 触发条件
- TEST 阶段完成，自动进入

### AI 自动动作

#### 开发项目
```
1. 读取 CHECKLIST.md → 获取部署检查清单
2. 逐项执行检查 → 环境、配置、依赖
3. 执行部署 → 按部署步骤
4. 验证部署 → 健康检查、核心功能验证
5. 配置监控 → 日志、告警
6. 如部署失败：
   a. 记录到 LOG.md
   b. 执行回滚
   c. 回到 TEST 阶段
7. 部署成功 → 自动流转到 DONE
```

#### 量化策略
```
1. 读取 CHECKLIST.md → 获取上线检查清单
2. 模拟盘验证 → 纸交易测试
3. 小资金实盘 → 观察 1-2 天
4. 验证裸仓保护 → 确认无裸仓
5. 配置监控 → TG 推送、告警
6. 如异常：
   a. 记录到 LOG.md
   b. 执行回滚
   c. 回到 TEST 阶段
7. 正常运行 → 自动流转到 DONE
```

### 自动产出
- 部署确认
- 监控配置确认
- 更新的 LOG.md

### 流转条件（自动判断）
- ✅ 进入 DONE：部署成功，验证通过，监控正常
- ❌ 回滚 TEST：部署失败 → AI 自动回滚并记录

---

## DONE 阶段 — AI 自动执行

### 触发条件
- DEPLOY 阶段完成，自动进入

### AI 自动动作
```
1. 最终自检 → 按 CHECKLIST.md DONE 检查项
2. 确认所有文档完整 → PRD/ARCH/TEST/LOG/Task
3. 确认代码已 push
4. 生成项目总结 → 写入 LOG.md
5. 标记 STATUS: DONE
6. 通知用户 → 输出完成报告
```

### 完成定义（全部满足）
- [ ] 所有功能完成
- [ ] 所有测试通过
- [ ] 成功部署
- [ ] 文档完整
- [ ] 日志完整

## 自动化总则

### 自动判断表
| 判断点 | AI 自动动作 |
|--------|-------------|
| 项目类型 | 根据关键词自动判断 |
| 任务依赖 | 根据模块关系自动推导 |
| 测试是否通过 | 自动分析测试结果 |
| 是否可流转 | 自动检查 CHECKLIST |
| 是否需回滚 | 自动判断错误类型 |

### 自动记录表
| 事件 | 自动记录到 |
|------|------------|
| 状态变更 | LOG.md + status.md |
| 任务完成 | Task.md + LOG.md |
| 测试失败 | TEST.md + LOG.md |
| 代码变更 | Git commit + LOG.md |
| 文档更新 | Git commit + LOG.md |

### 自动回滚表
| 失败场景 | 回滚动作 |
|----------|----------|
| 测试不通过 | TEST → DEVELOP，修复后重测 |
| 部署失败 | DEPLOY → TEST，检查后重部 |
| 文档缺失 | 回到对应阶段补文档 |
| 编译错误 | DEVELOP 内部修复 |
