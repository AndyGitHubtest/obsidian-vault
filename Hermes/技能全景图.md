### 🌐 Open-Claude-Cowork 体系 (3 个核心技能)

这是从 OpenClaude 项目衍生并深度整合的技能体系，用于在 macOS 桌面端运行非 Anthropic 模型的 Agent。

#### 1. `open-claude-cowork-setup` — 设置与配置
- **核心架构**: Electron 封装 `@anthropic-ai/claude-agent-sdk`
- **关键发现**: 所有中国提供商（GLM、DashScope、Kimi、DeepSeek、MiniMax）**仅支持 OpenAI 格式**，直接连接全部 404
- **唯一解法**: LiteLLM proxy 做 Anthropic → OpenAI 协议转换
- **配置位置**: `~/.claude/settings.json`（非 .env）
- **持久化**: launchd（非 nohup）
- **CLI 模式**: `npx tsx src/cli/cli-run.ts` 终端自主执行
- **Git**: 推送到 `fork` remote（origin 403）

#### 2. `open-claude-cowork-auto-loop` — 自主模式
- **自动继续**: 完成后自动识别下一步
- **AskUserQuestion 自动批准**: 不再阻塞
- **空闲检测**: 45s 无输出 → 自动恢复
- **错误重试**: 指数退避（2s/4s/8s）
- **tmux 持久化**: 终端关闭后继续运行
- **关键陷阱**: 必须用 `forkResume: true`（非 `resume`）

#### 3. `anthropic-sdk-china-providers` — 中国提供商配置
- **格式不兼容**: Anthropic SDK 用 `/v1/messages`，提供商只提供 `/v1/chat/completions`
- **SiliconFlow**: 唯一原生支持 Anthropic 格式的国内提供商
- **LiteLLM 桥接**: 本地代理转换协议
- **模型别名**: 用 `claude-opus-4-6` 绕过 UI 验证
- **通配符路由**: `"*"` 映射到后端模型
- **心跳自动恢复**: launchd 心跳服务监控代理
