## 二、 核心架构 (Core Architecture)

采用 **Asyncio 协程池 + 独立 Actor 状态机** 架构，实现高并发、隔离运行。

1.  **数据层**: 混合模式 (Hybrid Mode)
    *   **历史数据**: 本地 SQLite (只读)，用于加载 288 根 K 线窗口。
    *   **实时数据**: **WebSocket 订阅** (深度/Ticker)，提供 <50ms 延迟的最新价格。
2.  **计算层**: 动态 Kalman 滤波 + 8 因子打分。
3.  **执行层**: 防裸仓同步 (Anti-Naked-Position) + Maker/Taker 智能路由。
4.  **风控层**: 三级熔断 (Kill Switch) + 相关性破裂检测。
5.  **调度层**: 热加载 (Hot-Reload) + Watchdog 守护。

## 三、 模块详解 (Module Details)

### 3.1 模块一：数据与信号计算 (Data & Signal)

**职责**: 提供高精度、实时的 Z-Score (价差偏离度)。

*   **数据流向**: `SQLite` -> `Memory Array` -> `WebSocket Tick` -> `Kalman` -> `Z-Score`
*   **逻辑细节**:
    *   **预热**: 启动时加载 `pairs_v2.json` 指定的 288 根 K 线 (5m/15m/30m)。
    *   **Kalman 滤波**: 实时更新对冲比率 $eta$ (Beta)，不使用静态值。
    *   **Spread 公式**: $S_t = \log(P_A) - eta_t \cdot \log(P_B)$
    *   **Z-Score 计算**: $Z_t = (S_t - \mu) / \sigma$ (使用 288 窗口的动态均值和标准差)。
    *   **信号触发**: 当 $|Z_t| \ge E$ 时触发信号。

### 3.2 模块二：信号确认与过滤 (Signal Confirmation)

**职责**: 过滤假突破 (Fakeout)，确保信号有效性。

*   **双确认机制 (Dual-Confirmation)**:
    *   **触发**: $5m$ $Z$ 触及 $E$。
    *   **监控**: 启动 3 分钟倒计时。
    *   **投影确认**: 利用 WebSocket 实时价格，**EMA 平滑 (α=0.3)** 投影计算瞬时 $Z$。若 $Z \ge E + 0.2$，确认通过。
*   **假突破防御**:
    *   若 2 分钟内 $Z$ 回落至 **动态阈值** 以下 ($1.5 	imes 	ext{VolRatio}$)，判定为假突破。
    *   **动作**: 取消信号，进入 30 分钟冷却 (Cooldown)。
*   **超时处理**: 3 分钟内既未确认也未假突破，重置状态。
*   **Z 值熔断**: 若 $Z \ge 4.5$，判定为极端异常，**放弃开仓**。

### 3.3 模块三：匹配与扫描 (Matching & Scanner)

**职责**: 每 8 小时筛选 Top 30 配对并优化参数。

*   **漏斗筛选**:
    *   **L1 (极速)**: Pearson 相关性 > 0.6 (Numpy 矩阵)。
    *   **L2 (赛马)**: **8 核心算法** (Pearson, ADF, Kalman, Half-Life, Rolling Corr, Hurst, Rolling Vol, OU) $	imes$ 4 周期 (1m/5m/15m/30m)。
    *   **L3 (打分)**: 8 因子综合打分 (Z 速度, 相关性, Beta 稳定性等)，取最高分配置。
*   **参数优化 (Optuna)**:
    *   仅优化 3 个参数: **$E$ (进场)**, **$X$ (出场)**, **$S$ (止损)**。
    *   约束: $1.0 \le E \le 5.0$, $0.1 \le X \le E-0.2$, $E+1.0 \le S \le E+2.0$。
*   **实盘动态适配 (Volatility Adapter)**:
    *   $Real\_E = E_{base} 	imes (\sigma_{current} / \sigma_{historical})$。根据当前波动率自动缩放阈值。

### 3.4 模块四：执行与仓位管理 (Execution)

**职责**: 将信号转化为成交，严控滑点与裸仓风险。

*   **分层进场 (Layered Entry)**:
    *   Layer 1 ($E-0.3$): 30% 仓位。
    *   Layer 2 ($E$): 30% 仓位。
    *   Layer 3 ($E+0.5$): 40% 仓位。
    *   **贪婪跳层**: 若 Z 瞬间穿透多层，直接合并计算差额，一次性市价补齐。
*   **防裸仓同步 (Anti-Naked Protocol)**:
    *   A 腿成交 -> 检查 B 腿状态。
    *   若 B 腿 1s 内未成交 -> **立即市价平仓 A 腿** (不惜成本，绝不留单边)。
*   **智能路由**:
    *   **开仓/再平衡**: 深度预检 -> Maker 挂单 (2s) -> 未成交转 Taker。
    *   **止损/强平**: **100% 跳过 Maker，直接 Taker 市价单**。
*   **动态对冲**: 根据最新 Kalman Beta 计算目标仓位 ($Pos_B = Pos_A 	imes eta$)。

### 3.5 模块五：风控与异常保护 (Risk & Safety)

**职责**: 资金安全的最后一道防线。

*   **配对级风控**:
    *   **相关性破裂**: 滚动相关性 < 0.3 -> **立即市价全平**。
    *   **失衡监控**: 仓位偏离 > 5% 持续 5 分钟 -> 强平。
*   **账户级熔断 (Kill Switch)**:
    *   **Soft (5%)**: 停止开新仓，现有持仓继续。
    *   **Hard (10%)**: 市价全平所有持仓，休眠至次日 00:00。
    *   **Emergency (20%)**: 全平 + 断开 API + 紧急报警。
*   **基础设施**:
    *   **Watchdog**: 1 分钟无心跳 -> 强制重启 Actor。
    *   **孤儿仓位**: 扫描剔除但有持仓 -> 减半最大持仓时间 (60min) -> 超时强平。

## 四、 调度与运维 (Dispatch & Ops)

*   **热加载 (Hot Reload)**:
    *   每 8 小时更新 `pairs_v2.json`。
    *   **Diff 机制**: 新增 -> Spawn Actor; 剔除无持仓 -> Kill Actor; 剔除有持仓 -> 转孤儿模式。
    *   **原子替换**: 扫描结果先写 `.tmp`，后 `os.rename()` 覆盖，防止读取半截文件。
*   **监控**:
    *   Telegram 推送 (4 级: Info, Trade, Risk, Emergency)。
    *   Systemd 守护主进程 (自动重启)。
