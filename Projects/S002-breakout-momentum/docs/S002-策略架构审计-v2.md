# S002 动量突破策略 — 深度架构审计报告

> 审计人视角：10 年量化交易架构师。重点审视"回测能过但实盘会亏"的隐形陷阱。

---

## 一、逻辑漏洞诊断（直击痛点）

### 🔴 VULN-01：前低确认算法 — 长下影线陷阱

**当前写法：**
```python
pullback_low = np.min(low[breakout_idx+1 : -2])
```

**致命问题：**
1. **长下影线即"噪音支撑"**：一根 5m K 线的下影线可能是 10-20 秒的闪电崩盘/插针，随后迅速收回。`np.min(low)` 会把这个瞬间极值当成"支撑"，止损就设在这个位置下方 ATR*1.5 处——实盘中这相当于没止损。
2. **切片边界脆弱**：`breakout_idx+1 : -2` 在实盘中当回调 K 线数量 < 3 时返回空数组或极短数组，`np.min` 行为不确定。
3. **不包含当前跳动 K 线**看似合理，但 `-2` 的硬编码意味着如果回调只走了 2 根 K 线，切片为空——实盘中完全可能。

**实盘后果：** 止损线被极端下影线拉到不合理的位置，导致止损过远（仓位变小）或过近（被正常波动扫出）。

**严重度：P0**

---

### 🔴 VULN-02：回调进场 = 系统性踏空

**问题：** "必须等待回调" + "绝不追高" 的设计，在加密货币市场的强趋势行情中会导致严重踏空。

**数据直觉：**
- 加密货币的爆发性突破中，约 40-60% 的行情在突破后前 3-5 根 K 线内不回踩到突破位以下
- 这些不回踩的行情往往是动能最强、盈亏比最高的
- 死等回踩 = 自动过滤掉了最强的趋势

**举例：** BTC 从 $80,000 突破 $81,000 阻力位，直接拉到 $85,000 才首次回踩 $82,000。此时：
- 已经错过了 6.25% 的涨幅
- 回踩的 $82,000 远高于突破位 $81,000
- 止损设在 $82,000 - ATR*1.5 ≈ $80,500
- 盈亏比严重劣化

**严重度：P0**

---

### 🔴 VULN-03：TP1 强制保本 vs 宽止损 — 结构性矛盾

**问题公式：**
```
TP1 = max(5m前高, 入场价 + 风险 × 1.05)
止损 = 回踩前低 - ATR × 1.5
```

**矛盾分析：**

| 场景 | 止损距离 | TP1 距离 | 触发概率 |
|------|----------|----------|----------|
| 窄幅回调（回踩浅） | ATR × 0.8 | 入场 + ATR × 0.84 | 高 ✅ |
| 深度回调（回踩深） | ATR × 2.5 | 入场 + ATR × 2.625 | 低 ❌ |
| 突破位远离前高 | ATR × 1.5 | 取决于前高位置 | 不确定 ⚠️ |

**核心矛盾：** 回调越深，止损越宽，TP1 越远。但回调越深的行情往往动能越弱——TP1 反而更难到达。这就形成了一个"止损越宽→TP1越远→触发概率越低→持仓越久→时间止损风险越大"的恶性循环。

**实盘后果：** 深度回调进场后，价格缓慢向 TP1 移动但始终差一口气，48 小时后被时间止损踢出，亏损 ATR × 2.5。

**严重度：P0**

### 🟠 VULN-04：48 小时时间止损 — 严重偏长

**问题：** 5m 级别的动量策略，最长持仓 48 小时（576 根 K 线）。

**分析：**
- 动量突破策略的"alpha 半衰期"通常在 2-12 小时内
- 48 小时已经脱离了动量策略的时间框架，变成了趋势跟踪
- 超过 12 小时未触发 TP1 的持仓，统计上大概率不会触发了
- 资金被锁定 48 小时的机会成本极高（同一笔资金本可以捕捉 4-8 次新的突破信号）

**建议：** 
- 未触发 TP1：缩短到 **8-12 小时**（96-144 根 5m K 线）
- 触发 TP1 后：可以放宽到 **24-48 小时**（此时已经是盈利单，资金效率不是问题）

**严重度：P1**

### 🟠 VULN-05：多周期阻力位的数据一致性

**问题：** TP2-TP5 使用 15m/30m/1h/2h 阻力位作为止盈目标。

**实盘风险：**
1. **跨周期阻力位重叠**：15m 前高可能恰好等于 30m 前高，导致 TP2 和 TP3 几乎同时触发，丧失了分批止盈的意义
2. **阻力位距离不均匀**：可能 TP2 在入场价 +0.3%，TP3 在 +5%，中间有巨大的 gap
3. **动态变化**：大周期阻力位随着新 K 线收盘不断变化，持仓期间 TP 目标会漂移

**建议：**
- 在入场时**锁定**所有 TP 价格（snapshot）
- 检查 TP2-TP5 之间至少有 0.5% 的间距，否则合并批次

**严重度：P1**

**当前描述：** "缩量企稳" — 但没有量化的阈值。

**问题：**
- 缩量是相对谁的均值？突破前 N 根？全局均值？
- 企稳需要几根 K 线？1 根？3 根？
- 缩量企稳 + 再次放量 — 这两个信号之间的时间窗口是多长？

**实盘后果：** 信号定义模糊 → 回测和实盘行为不一致。

### 🟡 VULN-07：TP6 移动止盈 — 5% 仓位的尾部风险

**问题：** 保留 5% 仓位做移动止盈，追踪 3 倍 ATR。

**分析：**
- 5% 仓位太小，即使抓住大行情，对整体 PnL 贡献有限
- 3 倍 ATR 在 5m 级别可能过宽（5m ATR 通常很小，3 倍也不大）
- 但这 5% 的单子在极端行情中可能回吐所有已实现利润

**建议：**
- 考虑将 TP6 提升到 10%，尾部行情值得更多暴露
- 当 TP4/TP5 触发后，TP6 的追踪止损应收紧到 1.5-2.0 ATR

**严重度：P2**

## 二、前低确认算法 — 优化版

### 问题总结

`np.min(low[breakout+1:-2])` 的三个致命缺陷：
1. 被长下影线/插针误导
2. 回调 K 线数不足时行为不确定
3. 只看价格不看结构

### 优化方案：三重过滤支撑位确认

```python
import numpy as np
from dataclasses import dataclass
from typing import Tuple, Optional


@dataclass
class PullbackAnalysis:
    """回踩分析结果"""
    support_level: float        # 确认的支撑位
    stop_loss: float            # 计算的止损价
    confidence: float           # 置信度 0-1
    method: str                 # 使用的方法
    n_pullback_bars: int        # 回踩K线数量
    is_valid: bool              # 回踩是否有效


def fractal_low_support(
    low: np.ndarray,
    high: np.ndarray,
    close: np.ndarray,
    volume: np.ndarray,
    atr: np.ndarray,
    breakout_idx: int,
    current_idx: int,
    left_bars: int = 2,
    right_bars: int = 2,
) -> Optional[Tuple[float, int]]:
    """
    分型低点检测 (Bill Williams Fractal 变体)
    
    分型低点定义：
    - 该 K 线低点 < 左侧 N 根低点
    - 该 K 线低点 < 右侧 N 根低点
    
    实盘适配：右侧只用到 current_idx-1，不依赖未来数据。
    """
    if current_idx - breakout_idx < left_bars + right_bars + 1:
        return None  # K线数量不足，无法确认分型
    
    search_start = breakout_idx + 1
    search_end = current_idx - right_bars  # 留右侧空间确认
    
    best_fractal = None
    best_fractal_idx = -1
    
    for i in range(search_start + left_bars, search_end):
        # 左侧检查
        left_lows = low[i-left_bars:i]
        # 右侧检查（已收盘的K线）
        right_lows = low[i+1:i+1+right_bars]
        
        if len(right_lows) < right_bars:
            continue  # 右侧未收完，不确认
            
        if low[i] < np.min(left_lows) and low[i] < np.min(right_lows):
            # 找到分型低点
            if best_fractal is None or low[i] < best_fractal:
                best_fractal = low[i]
                best_fractal_idx = i
    
    return (best_fractal, best_fractal_idx) if best_fractal is not None else None


def volume_weighted_support(
    low: np.ndarray,
    close: np.ndarray,
    volume: np.ndarray,
    breakout_idx: int,
    current_idx: int,
    min_bars: int = 3,
) -> Optional[float]:
    """
    成交量加权支撑位
    
    逻辑：成交量密集区域的平均价格才是真正的支撑，
    而非单纯的最低价。低成交量的插针不应该被计入。
    """
    pullback_vol = volume[breakout_idx+1:current_idx]
    pullback_low = low[breakout_idx+1:current_idx]
    pullback_close = close[breakout_idx+1:current_idx]
    
    if len(pullback_vol) < min_bars:
        return None
    
    # 过滤掉成交量低于中位数 50% 的K线（噪音/插针）
    vol_median = np.median(pullback_vol)
    valid_mask = pullback_vol >= vol_median * 0.5
    
    if np.sum(valid_mask) < 2:
        # 有效K线太少，退回到 VWAP
        total_vol = np.sum(pullback_vol)
        if total_vol == 0:
            return np.min(pullback_low)
        return np.sum(pullback_low * pullback_vol) / total_vol
    
    # 成交量加权平均低点
    valid_lows = pullback_low[valid_mask]
    valid_vols = pullback_vol[valid_mask]
    
    return np.sum(valid_lows * valid_vols) / np.sum(valid_vols)


def pivot_support(
    low: np.ndarray,
    high: np.ndarray,
    breakout_idx: int,
    current_idx: int,
    pivot_len: int = 3,
) -> Optional[float]:
    """
    Pivot 点支撑
    
    寻找回调期间形成的 Pivot Low（左右各 pivot_len 根K线的最低点）
    """
    if current_idx - breakout_idx < pivot_len * 2 + 1:
        return None
    
    search_end = current_idx - pivot_len
    pivot_lows = []
    
    for i in range(breakout_idx + pivot_len, search_end):
        left_min = np.min(low[i-pivot_len:i])
        right_min = np.min(low[i+1:i+1+pivot_len])
        
        if low[i] <= left_min and low[i] <= right_min:
            pivot_lows.append(low[i])
    
    if not pivot_lows:
        return None
    
    # 取最近的 Pivot Low（最相关）
    return pivot_lows[-1]


def confirm_pullback_support(
    low: np.ndarray,
    high: np.ndarray,
    close: np.ndarray,
    volume: np.ndarray,
    atr: np.ndarray,
    breakout_idx: int,
    current_idx: int,
    atr_mult: float = 1.5,
) -> PullbackAnalysis:
    """
    ==================== 核心入口函数 ====================
    
    三重过滤支撑位确认，综合 Fractal + Volume-Weighted + Pivot 三种方法
    
    参数:
        breakout_idx: 突破信号K线索引
        current_idx: 当前K线索引（即将收盘或已收盘）
        atr_mult: ATR 止损乘数，默认 1.5
    
    返回:
        PullbackAnalysis 对象，包含支撑位、止损价、置信度
    """
    n_pullback = current_idx - breakout_idx - 1
    
    # ---- 前置检查 ----
    if n_pullback < 2:
        return PullbackAnalysis(
            support_level=0, stop_loss=0, confidence=0,
            method="insufficient_data", n_pullback_bars=n_pullback,
            is_valid=False
        )
    
    pullback_lows = low[breakout_idx+1:current_idx]
    
    # ---- 方法1：Fractal 分型低点 ----
    fractal_result = fractal_low_support(
        low, high, close, volume, atr,
        breakout_idx, current_idx, left_bars=2, right_bars=2
    )
    
    # ---- 方法2：成交量加权支撑 ----
    vw_support = volume_weighted_support(
        low, close, volume, breakout_idx, current_idx, min_bars=3
    )
    
    # ---- 方法3：Pivot Low ----
    pivot_lvl = pivot_support(low, high, breakout_idx, current_idx, pivot_len=3)
    
    # ---- 综合决策 ----
    candidates = []
    methods_used = []
    
    if fractal_result is not None:
        candidates.append(fractal_result[0])
        methods_used.append(f"fractal@{fractal_result[1]}")
    
    if vw_support is not None:
        candidates.append(vw_support)
        methods_used.append("vol_weighted")
    
    if pivot_lvl is not None:
        candidates.append(pivot_lvl)
        methods_used.append("pivot")
    
    # 如果至少两种方法达成一致（差值 < 0.3%），使用共识值
    if len(candidates) >= 2:
        candidates_sorted = sorted(candidates)
        min_spread = min(candidates_sorted[i+1] - candidates_sorted[i] 
                        for i in range(len(candidates_sorted)-1))
        avg_price = np.mean(candidates_sorted)
        
        if min_spread / avg_price < 0.003:  # 0.3% 以内算一致
            support = np.min(candidates)  # 保守取最低
            confidence = 0.8 + 0.2 * (len(candidates) / 3.0)
            method = f"consensus({','.join(methods_used)})"
        else:
            # 分歧较大，取成交量加权支撑（最可靠）
            support = vw_support if vw_support is not None else np.min(pullback_lows)
            confidence = 0.5
            method = "divergence_fallback"
    elif len(candidates) == 1:
        support = candidates[0]
        confidence = 0.6
        method = methods_used[0]
    else:
        # 所有方法都失败 — 退化到传统方法但加过滤
        # 过滤掉极端下影线：只考虑收盘价接近低点的K线
        pullback_closes = close[breakout_idx+1:current_idx]
        pullback_highs = high[breakout_idx+1:current_idx]
        
        # 下影线占比 < 30% 的K线才算有效低点
        body_sizes = np.abs(pullback_closes - np.array([
            (high[breakout_idx+1:current_idx][i] + pullback_lows[i]) / 2 
            for i in range(len(pullback_lows))
        ]))
        # 简化：用收盘价代替——收在低点附近的才算
        valid_low_mask = (pullback_closes - pullback_lows) / (pullback_highs - pullback_lows + 1e-10) < 0.3
        
        if np.sum(valid_low_mask) > 0:
            support = np.min(pullback_lows[valid_low_mask])
            confidence = 0.4
        else:
            support = np.min(pullback_lows)
            confidence = 0.2
        
        method = "degenerate_filtered_min"
    
    # ---- 止损计算 ----
    current_atr = atr[current_idx - 1] if len(atr) > current_idx - 1 else np.mean(atr[-20:])
    stop_loss = support - (current_atr * atr_mult)
    
    return PullbackAnalysis(
        support_level=support,
        stop_loss=stop_loss,
        confidence=confidence,
        method=method,
        n_pullback_bars=n_pullback,
        is_valid=confidence >= 0.4  # 低于 0.4 不建议进场
    )
```

### 算法设计原则

| 方法 | 权重 | 适用场景 | 优势 |
|------|------|----------|------|
| Fractal 分型 | 高 | 回踩 K 线 ≥ 5 根 | 结构明确，噪音过滤好 |
| Volume-Weighted | 中 | 任何情况 | 量价结合，排除低量插针 |
| Pivot Low | 中 | 回踩 K 线 ≥ 7 根 | 经典技术分析，市场共识 |
| 退化过滤 min | 低 | 数据不足时 | 比裸 np.min 好 |

### 关键改进点

1. **排除低成交量插针**：成交量低于中位数 50% 的 K 线不计入支撑计算
2. **多方法交叉验证**：至少两种方法共识时才给高置信度
3. **分型右侧确认**：Fractal 需要右侧 2 根已收盘 K 线确认，不依赖未来数据
4. **退化方案有过滤**：即使所有高级方法都失败，退化方案也过滤了极端下影线
5. **置信度系统**：低于 0.4 置信度直接不建议进场

## 三、参数微调建议

### 3.1 进场模式 — 折中方案：双轨制

**问题：** 死等回踩踏空率 > 50%。

**建议：双轨进场（Track A + Track B）**

```yaml
entry:
  track_a_pullback:  # 主轨道（70% 仓位）
    enabled: true
    min_pullback_bars: 3          # 至少 3 根回踩 K 线
    max_pullback_depth_pct: 0.02  # 回撤不超过突破位 2%
    stabilization_body_ratio: 0.8  # 实体小于突破 K 线的 80%
    trigger_vol_ratio: 1.2        # 放量 > 1.2x 均量
    position_pct: 0.70            # 占总仓位 70%
  
  track_a_momentum:   # 辅轨道（30% 仓位）
    enabled: true
    # 不回踩直接追——但条件更苛刻
    required_score: 85            # 评分必须 > 85（顶级信号）
    min_breakout_body_pct: 0.01   # 突破实体 > 1%
    min_vol_ratio: 3.0            # 量比 > 3x（确认是真突破）
    max_entry_delay: 3            # 最多延迟 3 根 K 线
    position_pct: 0.30            # 占总仓位 30%
    # 追仓的止损更紧：用突破 K 线低点，不用回踩前低

```

**逻辑：**
- Track A（70%）：正常回踩进场，止损用优化后的前低算法
- Track B（30%）：极强信号直接追，止损用突破 K 线低点（更紧）
- 综合效果：不再系统性踏空最强趋势，同时大部分仓位仍有安全边际

### 3.2 TP1 矛盾 — 动态最小盈亏比

**问题：** 止损越宽，TP1 越远，越难触发。

**建议：TP1 不再刚性绑定止损距离**

```python
def calc_tp1_price(entry_price, pullback_low, atr, five_min_high, friction_cost=0.001):
    """
    TP1 = max(5m前高, 入场价 + 动态最小利润)
    
    动态最小利润 = min(风险 * 1.05, ATR * 0.8)
    即：TP1 不超过入场价 + 0.8 ATR，避免过远
    """
    risk = entry_price - (pullback_low - atr * 1.5)
    dynamic_min_profit = min(risk * 1.05, atr * 0.8)
    
    tp1_distance = max(five_min_high - entry_price, dynamic_min_profit)
    
    # 加上摩擦成本
    tp1 = entry_price + tp1_distance + entry_price * friction_cost
    
    return tp1
```

**核心思想：** TP1 的最大距离被 ATR * 0.8 封顶。如果止损很宽（回调深），TP1 不会因为要覆盖止损就设得很远——它会在一个合理的距离（0.8 ATR）先触发，确保资金效率。虽然 TP1 这次可能不覆盖全部亏损，但后续 TP2-TP5 会补足。

### 3.4 止盈比例优化

```yaml
tp_allocation:
  tp1: 0.35      # 35% — 保本/微利锁定
  tp2: 0.25      # 25% — 15m 阻力
  tp3: 0.15      # 15% — 30m 阻力（降低）
  tp4: 0.10      # 10% — 1h 阻力
  tp5: 0.05      #  5% — 2h 阻力
  tp6: 0.10      # 10% — 移动止盈（从 5% 提升到 10%）
```

**调整理由：**
- TP3 从 20% 降到 15%：30m 和 15m 阻力往往很近，合并处理
- TP6 从 5% 提到 10%：尾部行情值得更多暴露，5% 太少没有意义
- 前两个 TP 保持 60%：确保大部分利润在阻力位锁定

### 3.5 关键参数汇总

| 参数 | 当前值 | 建议值 | 理由 |
|------|--------|--------|------|
